# PaperWright 产品愿景与架构

> 状态：v1 已定稿（2026-08-14）
> 定位：本文是 paperwright 从"本地确定性转换工具"迈向"规则内核 + 大模型判断层"混合架构的北极星文档。已定案决策见 §8。

---

## 1. 初衷与要解决的问题

**目标**：把复杂 PDF（以科研论文为代表）转换成**图文并茂的 Markdown 文档**。

**现状两难**：

| 路线 | 代表 | 优点 | 痛点 |
|---|---|---|---|
| 纯规则 / 固定脚本 | pymupdf4llm、pandoc、pdftotext | 快（0.01s/页）、零成本、可追溯 | 多栏乱序、表格坍塌、公式碎裂、图注错位，质量天花板低 |
| 机器学习 / 深度学习 | Marker、MinerU、Docling、Nougat | 表格/公式质量高 | 需 GPU、模型 1–2GB、部署门槛高、仍会乱序/删脚注 |

**行业趋势印证（2026）**：混合路线已成为主流——[pdfmux 的对比](https://pdfmux.com/blog/pdf-extractor-comparison-2026/) 中，拿 benchmark 第一的 OpenDataLoader 正是"规则 + AI 的混合引擎"；pdfmux 自身则靠"按页把文档路由到不同后端"取胜。这与本文的架构构想高度一致。

**本文的解法**：**确定性规则内核 + 可插拔的大模型判断层**，其中

- 纯文本模型为主（便宜），负责"这段是不是同一段""这行是不是标题"这类**文本判断**；
- 视觉模型为辅（贵），只负责"这页的版面区块怎么划""图注和图符不符"这类**几何/视觉判断**；
- 全程**尽量降低 token 消耗**（详见 §5）。

**"图文并茂"的准确定义**（已定案，2026-08）：

- **正文 → Markdown 文本**：由 PDFium 从文字层免费提取，规则重建阅读顺序；
- **表格 / Figure → 图片**：不做语义解析，由视觉模型/规则识别出区块边界后 `region-render` 成图嵌入；
- **公式 → 区分处理**：独立公式（独占一行的 display equation）图片化；**行内公式不图片化**，保留文字层原文，避免打断正文流；
- **图片 100% 保真**：数字、公式不会因"解析"被改动（正是 benchmark 里那 2 个工具"静默改数字"的反面）；
- 图片旁保留文字层降级文本（如当前 `> [!WARNING]` 表格降级），以维持可检索性；
- **演进路径**：等当前输出质量稳定后，再考虑"高质量语义表格 / 公式 LaTeX 化"，**作为新的选项或功能**（非默认行为），另定契约与成本预算。

## 2. 设计哲学（命门原则）

1. **LLM 只做判断，绝不转写**。
   正文文字一律由 PDFium 从 PDF 文字层免费提取；模型只回答布尔/分类/几何问题并返回结构化 JSON，**一个字都不转录**。
   依据：2026 年 [5 工具实测](https://dev.to/jeromebuilds/i-benchmarked-5-open-source-pdf-to-markdown-tools-for-rag-on-real-documents-2026-4heh) 发现 9 个工具里 2 个"静默改动了数字"——转写是幻觉与错误的主源。判断类输出（`SAME_PARAGRAPH` / `{role,bbox}`）出错概率与代价都远低于转写。

2. **确定性内核兜底，模型可替换**。
   坐标、阅读顺序、溯源（provenance）、Markdown 投影全部由规则确定；任何"视觉/文本模型"只要产出同一份契约 JSON 即可接入。模型坏了、403、掉线，都退回人工/规则路径，绝不伪造结果。

3. **校验器是唯一真值源，不是模型**。
   模型的每个结构化产物都要过 paperwright 自己的校验器（`validate-*`）。模型建议 ≠ 事实；校验失败就修正或降级，不弱化契约。

4. **可追溯优先**。
   每个元素保留来源（`source_ref`、confidence、`markdown_excluded_reason`），任何一次转换都能回溯"这句话从 PDF 哪里来"。

5. **token 预算意识**。
   转换成本要可度量（见 §5.3），并把"能规则就不模型、能文本就不视觉、能局部就不全文"作为默认路由原则。

## 3. 分层架构

```
                     ┌──────────────────────────────────────┐
                     │          校验器（validate-*）          │ ← 唯一真值源
                     └──────────────────────────────────────┘
                                        ▲
          ┌─────────────────────────────┼─────────────────────────────┐
          │             路由 / 分级（规则风险信号）                    │
          └─────────────────────────────┼─────────────────────────────┘
        ┌───────────────┐      ┌────────┴────────┐      ┌─────────────────┐
        │  L0 确定性内核 │      │ L1 纯文本判断层  │      │  L2 视觉判断层   │
        │  规则/脚本     │ ───► │  (便宜，主力)    │ ───► │   (贵，辅助)     │
        │  PDFium 提取  │      │  join-blocks     │      │  ROI / 区域划分  │
        │  布局候选      │      │ 格式整理        │      │  图注核查        │
        │  双栏阅读顺序  │      │ 产出 review.json│      │  产出 final-layout│
        │  Figure/表提取 │      │  极低 token      │      │  较高 token       │
        │  ¥0 / 0 token │      │                 │      │                  │
        └───────────────┘      └─────────────────┘      └─────────────────┘
                                        ▲                          ▲
                                        └────────────┬─────────────┘
                                                     ▼
                                     ┌──────────────────────────────┐
                                     │  L3 程序合成层（长尾最后手段） │
                                     │ 模型写 DSL 代码 → 产出 review │
                                     │ .json，复用同一套校验器       │
                                     └──────────────────────────────┘
```

**L0 确定性内核**（已实现，免费）：PDFium 原生文字层提取、跨页页眉页脚剔除（`--furniture`）、双栏阅读顺序、Figure/Caption 分组、manifest/provenance、三种布局提取配置（fast/standard/forensic）。L0 同时提供两样关键资产：**原语**（坐标、几何、词频统计，供上层调用）与**校验器**（"什么是对的"的判定标准）——规则不负责"做对"，只负责"验对"。

**L1 纯文本判断层**（直连桥已实现：`tools/run_text_review.py`）：`text-prepare` → 模型判断 → `validate-text-review` → `text-apply`。模型只做"跨块段落拼接（join-blocks）""格式整理""去连字符"等**文字判断**并产出 `review.json`，校验器重算并强制所有约束。

**L2 视觉判断层**（已跑通，见 `paperwright-vision-qwen` skill）：`layout-prepare` → 模型画 ROI/区域/图注核查 → `validate-final-layout` → `layout-apply`。模型只做**几何与语义判断**（content ROI、区域角色、阅读顺序、图注一致性），产出 `final-layout.json`，正文一个字不转录。

**L3 程序合成层**（最小原型已实现，内核已上游化，见 §8.3）：长尾版式（三列、侧栏、浮动注记等声明式操作无法表达的版式）的**最后手段，不是默认路径**。让模型写一段受限 DSL 代码，代码用**只读原语**分析块，最终 **emit 出与 L1 相同的 `review.json`** —— 复用同一套校验器，不旁路。三道护栏：

1. **受限 DSL（ast 白名单）**：只允许 if/for/字符串子集与 `api.*` 原语调用，禁 import/反射/递归/IO；
2. **声明式守恒校验**：`emit_join` 声明变换（加空格/去连字符），校验器重算规范化词频守恒——证明"结果无篡改"，而非信任"逻辑无错误"；
3. **落盘可复现**（✅ 已实现）：代码 + 输入哈希 + 输出一并写入 `_paperwright/06-text-review/`，同一输入重放得到同一输出。

同类版式被 AI 反复处理 N 次后，应**固化为新规则回填 L0**（AI 探索、规则沉淀），让规则库被使用经验喂养增长，而非人力穷举。

**路由/分级**（待实现，见 §7）：由规则风险信号（短碎片、图内标签泄漏、非文本入文本区、表格降级等）决定每个页面/区块走哪一层——能 L0 就不上 L1/L2；L1/L2 声明式表达不了才降级 L3。

## 4. 工具谱系定位

| 工具 | 路线 | 质量 | 门槛 | 图文并茂 | 可追溯 |
|---|---|---|---|---|---|
| pymupdf4llm | 纯规则 | 低–中 | 极低（纯 CPU） | 弱 | 弱 |
| pandoc / pdftotext | 纯规则 | 低 | 极低 | 否 | 否 |
| GROBID | 规则+传统 ML | 中（结构化元数据强） | 中 | 否 | 中 |
| Docling | 深度模型 | 高（表格 97.9%） | 高（模型+依赖） | 中 | 弱 |
| Marker / MinerU | 深度模型 | 高 | 高（需 GPU） | 中 | 弱 |
| OpenDataLoader | 规则+AI 混合 | 高 | 中–高（1–2GB 模型） | 中 | 中 |
| **paperwright** | **规则 + LLM 判断** | **中→高（随模型与分级）** | **低（纯 CPU，模型可云端/可替换）** | **高（图/图注/表格/锚点）** | **强（provenance 全链路）** |

paperwright 的差异化不在"某一项绝对质量最高"，而在：

- **门槛最低**：确定性内核纯 CPU 运行，LLM 层按需、可云端、可替换、可关闭；
- **可追溯最强**：从 PDF 元素到 Markdown 锚点的全链路 provenance；
- **成本可控**：转写免费，模型只花在"判断"上（§5）。

## 5. Token 经济学

### 5.1 命门：不做转写

正文转写是 token 大头，也是错误主源。paperwright 的正文来自 PDFium（0 token），模型 token 只花在结构化判断上。这是降本的第一性原理。

### 5.2 实测数据（本项目一次视觉复核，15 页论文）

| 手段 | 效果 |
|---|---|
| 关闭思维链（`enable_thinking=False` 或选非推理模型） | ROI 15 页 **515s → 28s**；reasoning tokens 从 2000+/页 → 0 |
| 强制结构化输出（`json_object` + few-shot 模板） | 模型只回 JSON，不回 prose，可解析性从 0/15 → 15/15 |
| 只喂单页最小图 | 每次约 1075 image tokens + 87 text tokens |

### 5.3 五大降本策略 → 映射到 paperwright

对应 [Eden AI 的 token 压缩五策略](https://www.edenai.co/post/token-compression-for-llms-reduce-api-costs)：

| 通用策略 | paperwright 落点 |
|---|---|
| semantic filtering（语义过滤） | 只喂判定所需的最小上下文：join-blocks 只喂"A 结尾 + B 开头"，不喂全文 |
| structured output（结构化输出约束） | `json_object` + 契约 Schema，一次产出可校验 JSON |
| chunking（上下文分块） | 逐页、逐块判定，不把整篇塞进上下文 |
| extraction（规则先筛） | 规则风险信号先路由：无风险页不调模型；只对高风险块调模型 |
| summarization（摘要压缩） | 判定任务天然无需摘要；若未来引入长上下文，可在工具输出层压缩 |

### 5.4 成本计量（部分实现）

- ✅ bridge 侧已记录每次模型调用的 input/output/reasoning tokens 与估算成本，
  写为 `paperwright-llm-cost-v0.1` 报告：L1 输出 `<review>.usage.json`，
  L3 输出 `synthesize-cost.json`，视觉桥输出 `visual-review-cost.json`；
- 待实现：`run.json` 聚合 per-step 用量，以及 CLI 预算上限和超限降级；
- 让"降 token"可度量：同一篇论文在不同路由/模型下的成本对比成为回归指标。

## 6. 当前状态 vs 目标差距

**已就绪**：L0 确定性内核；L1 纯文本直连桥（`tools/run_text_review.py`，Phase 1 已完成）；L2 视觉链路（含 `paperwright-vision-qwen` skill 与直连桥）；`validate-*` 全套校验器；`text-*` 协议与校验器；manifest/reader/article-model 三件套。

**差距（按性价比排序）**：

1. **表格/公式图片化已部分通用化**。`region-render-mode auto/explicit` 现在除 Figure 外，
   也会保守识别并渲染**同页表格**与**独立公式**（`content_render.py`）；行内公式仍保留文字层，
   渲染失败自动保留原生文本。仍需用真实论文评估识别准确率与图片体积。
2. **路由/分级未自动化**。规则风险信号已存在于质量检查里，但还没接成"决定调不调模型"的路由器。
3. **成本计量缺失**。没有 token/成本统计，优化无法度量。
4. **视觉协议对模型输出的鲁棒性**。实测模型产出有 bbox 变体、单对象、order=0、越 ROI 等形态变异，需把"模型输出 → 契约规范化"做成一等公民（官方 `normalize` 步骤，而非下游脚本补丁）。
5. **程序合成层（L3）最小原型已完成、上游化并带落盘溯源**。设计已定（§8.3）；join-blocks DSL 内核位于 `src/paperwright/synthesize.py`，`text-package --synthesis-run` 写出带确定性重放校验的 manifest v0.11。剩余差距是更广操作集与成本计量。

## 8. 已定案决策与设计待办

### 8.1 已定案（2026-08）

- 表格与 Figure：图片化，不做语义解析；
- 独立公式（display equation）：图片化；行内公式：不图片化，保留文字层原文；
- 语义表格 / 公式 LaTeX 化：**暂缓**，待当前输出质量稳定后作为新的选项/功能评估；
- 图片化与可检索性：默认"图片 + 文字层降级文本并存"；降级文本**不得干扰正文阅读**（设计待办见 8.2），并计划提供 `--images-only` 纯图片开关；
- 图片预算：提供 `--image-scale` 与 `--max-image-side` 可调参数，默认适中清晰度；
- 部署形态：本地 CLI + Agent skills；Web/API 服务**延后**；
- 模型策略：模型可配置（环境变量/配置），默认 qwen3.7-plus；403/超时自动回退，最终退回人工/规则，绝不伪造；支持任意 OpenAI 兼容端点；
- 成本上限：Phase 1 先做成本计量（run.json 记录 token 与估算成本），Phase 2 再上预算上限（超限自动降级到规则/人工）；
- 目标用户：科研人员自用 + Agent 生态组件双定位。

### 8.2 设计待办：降级文本不干扰正文阅读

"图片 + 降级文本并存"成立的前提是降级文本不打断阅读流。候选方案（按推荐排序）：

1. **折叠区**：`<details><summary>表格/公式原文（可检索）</summary>…</details>`，阅读时默认折叠、需要时展开；GitHub / VS Code / Typora 均支持；
2. **后置弱化**：降级文本移至图片下方，灰调小字（blockquote 或 `<sub>`）；
3. **正文外置**：正文只留图片与锚点链接，原文放 `_paperwright/` 附录（`reader.json` 已能承载全文）；
4. **不输出**：降级文本不进 `article.md`，仅在 `reader.json` 等 artifact 中保留。

推荐以 **1 为主、3 为辅**；Phase 1 实现时验证各 Markdown 渲染器的兼容性，并确认是否与"确定性、纯 Markdown 输出"的既有约定冲突。

### 8.3 已定案：L3 程序合成层（2026-08）

针对"规则难以泛化、AI 按需写代码"的构想，已对齐如下决策：

1. **定位**：长尾版式的**最后手段**，非默认路径——L1 优先，声明式表达不了（三列、侧栏、浮动注记等）才降级 L3；
2. **输出契约**：L3 产出的 review.json **与 L1 完全相同**，复用 `validate-text-review`，不旁路校验器——只换"判断逻辑的载体"（一次性推理 → 可复现代码）；
3. **执行形态**：受限 DSL，`ast` 白名单——允许 if/for（迭代上限）/字符串子集/`api.*` 原语，禁 import/反射/递归/IO/任意对象；
4. **原语 API**：只读查询（blocks/text_page/bbox/几何判定/词频）+ 结构化 emit（`emit_join` 等，声明意图而非执行）；
5. **守恒校验**：声明式——join 声明变换（加空格/去连字符），校验器重算规范化词频守恒；证明"结果无篡改"而非信任"逻辑无错误"；
6. **触发时机**：校验器报"声明式无法表达"或复杂版式信号时降级；用户可显式指定；
7. **可复现**（✅ 已实现）：代码 + 输入哈希 + 输出一并落盘 `_paperwright/06-text-review/`，`validate-text-package` 重新执行 DSL 证明同一输入重放得到同一输出；
8. **成本**：挂成本计量（§5.4），设预算上限，超限降级回 L1/规则；
9. **演进**：同类版式被 L3 反复处理 N 次 → 固化为新规则回填 L0（AI 探索、规则沉淀）；
10. **原型**：已完成 join-blocks 最小原型并验证可行性；内核位于 `src/paperwright/synthesize.py`，后续再扩展操作集。
